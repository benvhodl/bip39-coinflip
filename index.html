BIP39 Coin-Flip Entropy Generator

Generates entropy words from physical coin flips. Never the final word.
This application never constructs or stores the complete BIP39 mnemonic or complete entropy. At most, it temporarily holds the current entropy word and the flip data used to derive it, until you confirm you've written that word down. It stops one word short: a 12-word seed gets entropy words 1–11, a 24-word seed gets words 1–23. You generate the final word separately, using trusted hardware (or another explicitly trusted offline method) — see README.md for workflow details.

Security model & honesty notes
  • This app deliberately stops one word short. For a 12-word seed it generates entropy words 1–11 (the first 121 of the 128 entropy bits) and never touches word 12, which contains the remaining 7 entropy bits plus a 4-bit checksum. For a 24-word seed it generates words 1–23 (the first 253 of the 256 entropy bits) and never touches word 24, which contains the remaining 3 entropy bits plus an 8-bit checksum. The final word is not simply a checksum of the earlier words — it's a mix of leftover entropy and checksum bits computed from the complete entropy. This page contains no checksum code at all — not because it's turned off, but because it was never written. There is no button, mode, or hidden feature anywhere in this file that computes a final word, reconstructs full entropy, derives a seed, or builds an extended key (xprv/xpub).
  • Generate the final word using trusted hardware that supports entering externally generated entropy. This page intentionally doesn't walk you through that step or link anywhere — it's meant to be run offline, and documentation belongs in README.md, not in an executable page that might be opened on a networked machine.
  • Only one word's worth of state exists in memory at a time: the current word's physical flip history (or raw bits, in Standard mode) until it's converted into a word, and then just that one word's text until you confirm you've written it down. There is no array anywhere in this page holding your generated words as a growing list, no complete-entropy buffer, and no checksum. When you press "clear and continue," the completed word's text and all of that word's underlying flip/bit state are discarded before the next word begins. To be precise about what that means: the application removes its references to the completed word and clears its DOM representation. JavaScript cannot guarantee physical RAM erasure — "cleared" here means dereferenced and eligible for garbage collection, not securely wiped.
  • No localStorage, sessionStorage, cookies, IndexedDB, service workers, or network requests are used anywhere in this file. Nothing you do here is written to disk or sent anywhere. Reloading or closing the tab leaves nothing behind.
  • Standard mode records the physical landing face directly, one flip per bit. This page alternates which face you're asked to start each flip on (within a word) and which starting face begins each new word, as a technique intended to reduce exposure to known starting-side/same-side effects across the overall sequence — it is not a randomness extractor and does not guarantee unbiased or independent bits. Each word uses an odd number of flips (11), so this alternation balances out across pairs of words, not within any single word. The displayed starting face is a procedure for the physical toss, not itself an entropy bit: the only entropy input in Standard mode is the physical landing face you report.
  • Unlike some coin-flip tools, the starting-face pattern here is fully deterministic (alternating by word number and by flip number) rather than drawn from the browser's random number generator. This page uses no crypto.getRandomValues, Math.random, or any other software RNG anywhere, for anything. The tradeoff: an adversary who knows this algorithm could predict which face you're told to start on. That doesn't reduce the quality of your entropy below the baseline physical-coin bias described above, because the bit value recorded for any flip is always whatever the physical coin actually showed you, never a value derived from software — but it is a real, honestly-stated difference from a design that randomizes the starting face per word.
  • Bias-resistant mode uses a von Neumann extractor: physical flips are processed in pairs. Heads→Tails yields 1, Tails→Heads yields 0; Heads→Heads or Tails→Tails are discarded, and the next two physical flips form a new pair. Not every pair produces an output bit — with a fair coin, extracting one bit takes about 4 physical flips on average, not 2. This removes fixed heads/tails bias when consecutive observations can be modeled as independent trials with a stable but unknown probability of heads. It does not protect against arbitrary dependence between consecutive flips (for example, if how you catch or re-place the coin depends systematically on the previous outcome). The only entropy input in this mode is the sequence of physical landing faces.
  • Rotating physical coins prevents every entropy word from depending on the same physical coin, providing some source diversity. It does not guarantee independence or compensate for systematic bias shared across coins, and using more coins is not the same as generating more entropy. One physical coin is used for the entire current word — don't switch coins mid-word.
  • Ambiguous flips: if a coin lands on its edge, leaves the landing surface, is caught, is obscured, or you're not confident which face it landed on, don't guess. Press "Reset this word" and start that word's flips over. In Bias-resistant mode especially, an ambiguous flip must not be quietly treated as if it were a same-same discard — only a full word reset removes it cleanly from the record.
  • Physical flipping procedure: place the coin on the requested starting face (Standard mode) or however is convenient (Bias-resistant mode), flip it cleanly, let it land on a soft, level surface, and don't catch it. Then record the actual landing face.
Diagnostics — run self-tests

Runs deterministic checks against synthetic test vectors only (not your real flips): word-list self-consistency, an exhaustive 11-bit→word mapping check across all 2048 values, von Neumann extractor logic including exact single-flip undo, input validation, and internal state invariants. (The embedded word list was separately diffed against the canonical BIP39 English list, and the entropy→word mapping was cross-checked against official BIP39 test vectors, during development — this in-page suite re-checks internal consistency, not the canonical source, since this page makes no network requests.)
