Security model & honesty notes
  • This app deliberately stops one word short. For a 12-word seed it generates entropy words 1–11 and never touches word 12. For a 24-word seed it generates words 1–23 and never touches word 24. The omitted final word carries the BIP39 checksum; this page contains no checksum code at all — not because it's turned off, but because it was never written. There is no button, mode, or hidden feature anywhere in this file that computes a 12th or 24th word, reconstructs full entropy, derives a seed, or builds an xprv/xpub. The only cryptographic logic here is the deterministic mapping from 11 bits to one of the 2048 BIP39 words.
  • Get the final checksum word from a trusted hardware device that supports entering your own entropy, or from an explicitly trusted offline tool such as iancoleman's BIP39 tool run from its downloaded standalone build on an air-gapped machine — never on a machine that has also seen these entropy words over the network.
  • Only one word's worth of state exists in memory at a time. There is no array anywhere in this page holding your generated words as a growing list, and the page never displays more than the single word you just finished. When you press "clear and continue," that word's bits, its computed index, and the word text are all discarded before the next word begins.
  • No localStorage, sessionStorage, cookies, IndexedDB, service workers, or network requests are used anywhere in this file. Nothing you do here is written to disk or sent anywhere. Reloading or closing the tab leaves nothing behind.
  • Standard mode is one coin flip per bit. This page alternates which face you're asked to start each flip on (within a word) and which starting face begins each new word, and rotates through your coins — techniques intended to reduce known physical coin-toss biases, most notably the same-side bias documented in large empirical studies of real coin flips. This is honestly a mitigation, not a fix: it does not make a physical coin perfectly unbiased, and the resulting bits should not be assumed to be mathematically independent and identically distributed.
  • Unlike some coin-flip tools, the starting-face pattern here is fully deterministic (alternating by word number and by flip number) rather than drawn from the browser's random number generator. This page uses no crypto.getRandomValues, Math.random, or any other software RNG anywhere, for anything. The tradeoff: an adversary who knows this algorithm could predict which face you're told to start on. That doesn't reduce the quality of your entropy below the baseline physical-coin bias described above, because the bit value recorded for any flip is always whatever the physical coin actually showed you, never a value derived from software — but it is a real, honestly-stated difference from a design that randomizes the starting face per word.
  • Bias-resistant mode uses a von Neumann extractor: flip the coin twice per output bit; Heads→Tails yields 1, Tails→Heads yields 0, and Heads→Heads or Tails→Tails are discarded and re-flipped. This removes first-order heads/tails bias for any fixed-but-unknown coin bias, under the usual assumption that consecutive flips are independent trials. It does not guarantee perfect randomness against arbitrary correlations between flips (for example, if how you catch or re-place the coin depends systematically on the previous outcome). It does not claim to make the physical coin "perfectly random."
  • The "coins in rotation" setting cycles which physical coin you use, one per word, so a single coin's manufacturing defect or wear doesn't bias every word the same way.
